# 자리 — sitting-app

13층 플랫폼개발팀의 **21개 좌석**에 대해 개인별 **1~21지망**과 **함께 앉고 싶은 동료**를 입력하는 웹 앱입니다. 기본 배정은 **희망 동료 요청 충족 → 같은 파트 거리 → 개인 좌석 지망** 순서로 비교하며, 게일–섀플리 매칭을 사용합니다. 전원 랜덤 선호 생성, 완전 랜덤 좌석 추첨, 공개 Google Sheets 링크 입력도 지원합니다.

## 실행

**Node.js 22 이상**이 필요합니다. 외부 npm 패키지 설치 없이 실행할 수 있습니다.

```bash
git clone https://github.com/sunLeee/sitting-app.git
cd sitting-app
npm start
```

브라우저에서 **http://localhost:5180**을 엽니다. 서버를 종료할 때는 실행한 터미널에서 `Ctrl+C`를 누릅니다.

이미 내려받은 프로젝트에서는 프로젝트 폴더에서 `npm start`만 실행하면 됩니다. 포트가 사용 중이면 다른 포트를 지정하세요.

```bash
npm start -- --port 5181
```

기본 서버는 `127.0.0.1`에 연결됩니다. 같은 네트워크의 다른 기기에서 함께 입력할 때는 다음처럼 실행하고, 참여자는 서버를 실행한 컴퓨터의 IP 주소로 접속합니다.

```bash
npm start -- --host 0.0.0.0 --port 5180
```

참여자별 로그인은 구현되어 있지 않으며, 이름 선택으로 선호를 입력하는 내부 워크스페이스입니다.

## 사용 방법

1. **좌석 둘러보기**에서 구역과 실제 좌석 사진을 확인합니다.
2. **내 자리 선호**에서 본인 이름을 선택합니다.
3. 지도에서 좌석을 누르면 1지망부터 차례대로 추가됩니다. 중복 선택은 추가되지 않습니다.
4. 드래그 또는 위·아래 화살표로 순위를 바꿉니다. **남은 순위 자동 채우기**로 남은 좌석을 채운 뒤 수정할 수도 있습니다.
5. **C구역 함께 앉고 싶은 동료**를 선택할 수 있습니다. 다른 파트의 동료도 선택할 수 있으며, 짝 요청이 선택되면 두 사람 모두 C구역 짝 좌석으로 배정됩니다.
6. 21개 좌석을 모두 선택하고 **선호 저장하기**를 누릅니다. 수정 중인 순서와 희망 동료는 브라우저에 임시 저장되고, 배정에는 제출한 선호만 사용합니다.
7. 모든 참여자가 제출하면 **배정 시작하기**에서 시드와 배정 기준을 정합니다.
8. 결과 지도와 표에서 개인별 좌석·실제 배정 지망·희망 동료 충족 여부를 확인하고 **CSV**를 내려받습니다.

**미리 체험하기** 또는 `http://localhost:5180/?demo=1`은 예시 선호로 동작합니다. 예시 화면의 저장·배정·명단 수정은 실제 워크스페이스에 반영되지 않습니다.

## 올 랜덤으로 배정하기

상단의 **올 랜덤**을 누르고 두 방식 중 하나를 선택합니다.

| 방식 | 동작 | 기존 제출 선호 | 결과 지망 |
| --- | --- | --- | --- |
| 랜덤 선호 + 파트 거리 배정 | 전원의 21지망을 랜덤으로 생성한 뒤 저장된 희망 동료와 파트 거리를 반영한 게일–섀플리 배정 | 생성한 선호로 교체, 희망 동료 보존 | 생성한 선호 기준 표시 |
| 완전 랜덤 좌석 추첨 | 좌석을 시드 기반 Fisher–Yates 방식으로 섞어 한 사람에게 한 좌석 배정 | 보존 | 해당 없음 |

**완전 랜덤 좌석 추첨**은 선호 제출 없이 실행할 수 있습니다. 좌석 지망·희망 동료·파트는 좌석 선정에 영향을 주지 않으며, 게일–섀플리 안정성이나 파트 거리 최소화를 적용하지 않습니다. 표시되는 파트 거리는 추첨 결과의 거리입니다.

시드를 비워 두면 매번 새로운 시드를 만듭니다. 같은 명단·좌석·방식·시드를 사용하면 같은 결과를 재현할 수 있습니다. 시드는 결과에 표시됩니다. 실제 워크스페이스에서는 배정 결과를 저장하며, **랜덤 선호 + 파트 거리 배정**을 선택하면 기존 제출 선호도 갱신합니다.

## 공개 Google Sheets 링크로 배정하기

1. [좌석배정선호조사 시트](https://docs.google.com/spreadsheets/d/1Y--DqGO6stgAlMi5FTvLVXo29GsfJl9Zzu2mNWGh4fk/edit?gid=0#gid=0)에 기본 명단 20명과 24개 머리글이 채워져 있습니다. 각 행의 21지망과 선택 사항인 **함께 앉고 싶은 동료**를 작성합니다. 앱의 공개 시트 링크도 이 문서로 기본 설정되어 있습니다.
2. 시트의 **공유 → 일반 액세스 → 링크가 있는 모든 사용자 → 뷰어**로 설정하고 링크를 복사합니다. 또는 **파일 → 공유 → 웹에 게시**로 사용할 탭을 게시합니다. [Google 공유 안내](https://support.google.com/drive/answer/2494822?hl=ko), [웹에 게시 안내](https://support.google.com/docs/answer/183965?hl=ko)
3. 앱 상단의 **공개 시트로 배정**을 누르거나 **표·파일 가져오기**를 엽니다.
4. 공개 Google Sheets 링크를 입력하고 시드·배정 기준을 정한 뒤 **시트 불러와 배정**을 누릅니다. 기본값은 파트 거리 기준이며 개인 선호 기준도 선택할 수 있습니다.
5. 서버가 지정한 탭을 CSV로 읽고 모든 행을 검증한 뒤 좌석 지망과 희망 동료를 적용하고 배정 결과를 표시합니다.

일반 문서의 `/spreadsheets/d/…/edit` 링크와 웹에 게시한 `/spreadsheets/d/e/…/pubhtml` 링크를 사용할 수 있습니다. 링크에 `gid`가 있으면 해당 탭을 읽고, 없으면 `gid=0` 탭을 읽습니다. 비공개 시트나 로그인해야 열리는 링크는 사용할 수 없습니다.

이 기능은 **`npm start`로 실행한 Node 서버가 필요**합니다. 정적 호스팅에서는 아래의 붙여넣기·파일 가져오기를 사용하세요. 시트 CSV의 최대 크기는 1MiB이며 다운로드 제한 시간은 15초입니다.

공개 시트는 현재 참여자 명단에 맞춰 검증합니다. 일부 사람의 완성된 행만 있으면 기존 제출 선호와 합칩니다. **시트 불러와 배정**에서는 합친 뒤에도 미제출자가 남거나 한 행이라도 잘못된 입력이 있으면 선호를 적용하지 않고 오류를 표시합니다. **시트 미리보기** 후 **검증한 선호 가져오기**로 일부 사람의 완성된 선호만 저장할 수도 있습니다. 이름·파트를 바꾸려면 **참여자 관리**에서 먼저 수정하세요.

## Google Sheets 표 붙여넣기·파일 가져오기

**함께하는 사람들 → 표·파일 가져오기**에서 Google Sheets 표를 붙여넣거나 CSV/TSV 파일을 업로드할 수 있습니다.

1. **입력 양식** 또는 대화상자의 **빈 양식 다운로드**로 CSV를 받습니다.
2. Google Sheets에서 **파일 → 가져오기 → 업로드**로 CSV를 엽니다. A열은 이름, B열은 파트, C~W열은 1~21지망, X열은 **함께 앉고 싶은 동료**입니다.
3. 각 사람의 행에 21개 좌석 번호를 중복 없이 입력합니다. 이름은 명단과 같게, 파트는 `데이터`, `배차`, `맵`, 좌석은 `68`, `207`, `85`처럼 번호만 씁니다. 희망 동료는 등록된 이름 한 명을 쓰거나 비워 둡니다. 자기 자신을 선택할 수 없습니다.
4. 머리글과 작성한 행을 함께 복사해 **표·파일 가져오기**에 붙여넣습니다. 또는 **파일 → 다운로드 → 쉼표로 구분된 값(.csv)**으로 저장해서 업로드합니다.
5. **표 확인하기**로 미리보기와 오류 위치를 확인한 뒤 **검증한 선호 가져오기**를 누릅니다. 한 행이라도 잘못된 입력이 있으면 전체 가져오기를 보류합니다.

이름·파트·21개 지망 머리글의 순서는 바꿀 수 있고 추가 메모 열도 허용합니다. 기존 23열 표도 가져올 수 있으며, 희망 동료 열이 없으면 저장된 선택을 보존합니다. 희망 동료 열이 있는 표에서 빈칸은 해당 사람의 선택을 해제합니다. 일부 사람의 완성된 행만 가져와 기존 제출 내용과 합칠 수도 있습니다. 이름 또는 파트를 바꿔야 하면 **참여자 관리**에서 먼저 수정하세요. 기존 JSON 파일 가져오기도 계속 지원합니다.

빈 양식은 현재 명단을 반영합니다. 대화상자의 **제출 선호 CSV**로 이미 저장한 선호를 Google Sheets 형식으로 내보낼 수도 있습니다.

기본 시드 `jari-random-2026-10-28`의 결과: **20명 배정, 빈자리 B구역 82번, 평균 3지망, 3지망 이내 14명**입니다. 파트 거리 합은 개인 선호 기준 배정 대비 **37.9% 감소**했습니다. 개인 선호 기준 평균 지망은 2.75, 거리 고려 배정의 평균 지망은 3.00입니다.

명령은 예시 파일을 생성합니다. 생성한 파일을 앱의 **표·파일 가져오기**로 적용한 뒤 배정하면 실제 워크스페이스에서도 같은 결과를 볼 수 있습니다. 위 수치는 저장소에 포함된 예시 결과이며, **올 랜덤**의 새 시드로 추첨하면 결과가 달라집니다.

화면의 **랜덤 배정 결과 보기**는 실제 제출 내역을 바꾸지 않고 랜덤 예시를 바로 배정합니다. 직접 접속할 때는 `http://localhost:5180/?demo=1&random=1&view=results`를 사용할 수 있습니다.

## 좌석과 참여자

구역과 파트의 색상은 서로 다른 구분입니다.

| 구역 | 좌석 수 | 좌석 번호 | 전동 책상 | 모니터 | 좌/우 파티션 |
| --- | ---: | --- | --- | --- | --- |
| A | 9 | 207, 206, 205, 68, 69, 70, 73, 72, 71 | 있음 | 싱글 | 있음 |
| B | 6 | 79, 78, 77, 80, 81, 82 | 있음 | 싱글 | 없음 |
| C | 6 | 85, 90, 86, 89, 87, 88 | 없음 | 싱글 | 있음 |

| 파트 | 색상 | 초기 인원 |
| --- | --- | ---: |
| 데이터 | 파랑 | 8명 |
| 배차 | 노랑 | 8명 |
| 맵 | 빨강 | 4명 |

C구역의 두 사람 짝 좌석은 **85–90, 86–89, 87–88**입니다. 희망 동료 요청은 이 세 쌍 중 하나에 두 사람이 함께 배정될 때 충족됩니다.

제공된 명단의 초록색 인원은 제외했습니다. 초기 참여자는 **20명**이므로 **1석이 비어 있게** 배정합니다. **참여자 관리**에서 이름과 파트를 수정하거나 최대 21명까지 추가할 수 있습니다. 명단·제출 좌석 지망·희망 동료가 바뀌면 기존 결과를 해제하고 다시 배정합니다.

좌석·명단의 초기값은 `data.mjs`에서 관리합니다. 사진은 제공된 좌석 안내 이미지에서 추출했습니다.

## 배정 기준

### 파트가 가까워지는 배정 — 기본값

우선순위는 **희망 동료 요청 충족 수 최대화 → 같은 파트 거리 합 최소화 → 원래 좌석 지망 순위 합 최소화**입니다. 앞선 기준이 같은 후보끼리 다음 기준으로 비교합니다.

1. 희망 동료 요청을 두 사람의 짝으로 묶습니다. 한쪽만 요청하면 1건, 서로 요청하면 2건으로 셉니다. 한 사람은 한 짝에만 들어가며 C구역의 세 쌍을 사용합니다. 요청이 겹치거나 세 쌍을 초과하면 일부 요청은 충족되지 않을 수 있습니다.
2. 충족 가능한 요청 수가 최대인 짝 조합과 C좌석 배치를 모두 구합니다. 각 배치를 기본 게일–섀플리로 평가하고, 파트 거리와 원래 지망 순위가 좋은 상위 12개 배치를 추가 탐색합니다.
3. 선택된 짝의 두 사람은 각각 지정된 C좌석을 제안 순서 맨 앞에 두고, 나머지 좌석은 본인의 지망 순서를 유지합니다. 지정된 C좌석도 해당 사람을 최우선으로 받습니다. 이 선호와 우선순위는 매칭을 시작하기 전에 고정합니다.
4. 데이터·배차·맵 파트의 기준 좌석을 서로 다른 좌석에 둡니다. 21석의 기준 좌석 조합 `21 × 20 × 19 = 7,980`개를 비교합니다. 각 좌석은 가까운 기준 좌석을 가진 파트를 우선하며, 같은 파트 또는 거리 동률에서는 **시드로 정한 좌석별 우선순위**를 사용합니다.
5. 참여자는 고정된 제안 순서에 따라 좌석에 제안합니다. 좌석은 우선순위가 높은 사람을 유지하고, 밀려난 사람은 다음 좌석에 제안합니다. 이 과정이 **참여자 제안형 게일–섀플리**입니다.
6. 같은 파트에 속한 **모든 두 사람 사이의 유클리드 거리 합**을 비교합니다. 동료 요청 충족 수가 같으면 거리 합이 작은 결과를 선택하고, 거리 합도 같으면 **원래 제출한 좌석 지망 순위 합**이 작은 결과를 선택합니다. 결과에 표시하는 지망도 원래 제출한 순위입니다.

**희망 동료 요청 충족 수의 최댓값은 보장**합니다. 파트 거리는 모든 최대 동료 배치의 기본 평가와 상위 12개 배치의 기준 좌석 탐색 중 최솟값이며, 모든 가능한 좌석 배치에 대한 전역 최솟값을 보장하지 않습니다. 희망 동료가 없으면 기존과 같이 7,980개 기준 좌석 후보와 기본 후보 1개, 총 **7,981개**를 비교합니다.

게일–섀플리의 안정성은 **좌석 지망과 동료 요청을 결합한 고정 선호** 및 선택된 좌석 측 우선순위에 대해 검증합니다. 동료 요청 때문에 C좌석이 먼저 제안될 수 있으므로 원래의 좌석 지망만을 기준으로 안정성을 보장하지는 않습니다.

거리 좌표는 이미지의 상대 배치를 재현한 값이며 **미터 단위가 아닙니다**. 실측 거리로 계산하려면 `data.mjs`의 좌석 `x`, `y`를 실측 값으로 바꾸면 됩니다.

### 개인 선호 기준 배정

**희망 동료 요청 충족 수 → 개인 좌석 지망** 순서로 비교합니다. 파트 거리에 따른 우선순위 없이 시드로 좌석 측 우선순위를 정한 뒤, 동일한 게일–섀플리 방식으로 배정합니다. 동료 요청이 없으면 본인의 원래 지망 순서대로 제안합니다. 전체 지망 순위 합의 전역 최적화를 보장하지는 않습니다.

동일한 명단·좌석 지망·희망 동료·좌석·시드·배정 모드는 동일한 결과를 만듭니다. 처리 순서에 따라 유불리가 달라지지 않도록 참여자·좌석 ID를 정렬해 계산합니다. 배정 계산은 Web Worker에서 진행됩니다.

### 완전 랜덤 좌석 추첨

참여자와 좌석 ID를 정렬한 뒤 시드 기반 Fisher–Yates 셔플로 좌석을 섞습니다. 참여자별로 서로 다른 좌석 하나를 배정하고 남은 좌석은 빈자리로 표시합니다. 좌석 지망·희망 동료·파트는 추첨에 영향을 주지 않습니다. 개인 지망·평균 지망·3지망 이내 인원은 해당 없음으로 표시합니다. 이 방식에는 게일–섀플리나 거리 후보 탐색을 적용하지 않습니다.

## 저장과 파일 취합

- **Node 서버 실행:** 제출된 좌석 지망·희망 동료·명단·결과를 `.local-data/workspace.json`에 저장합니다. 같은 서버에 연결한 브라우저끼리 제출 내역을 공유하며, 서버 재시작 후에도 유지됩니다. 다른 브라우저의 저장 내역은 주기적으로 새로 확인합니다.
- **개인 임시 순서와 동료:** 각 브라우저의 `localStorage`에 저장합니다. 저장 버튼을 누르기 전까지 서버의 제출 내역을 바꾸지 않습니다. 저장 중에 다시 수정해도 새 임시 입력을 보존합니다.
- **개인 선호 파일:** 21개 순서를 선택한 뒤 **내 선호 파일 내려받기**로 좌석 지망과 희망 동료가 담긴 JSON을 내보냅니다.
- **파일 불러오기:** 개인별 파일을 취합하거나 전체 워크스페이스 백업을 가져옵니다. 개인 파일은 해당 참여자의 선호를 합치며, 전체 백업은 파일의 명단을 함께 적용합니다. 가져온 결과는 그대로 사용하지 않고 최신 선호로 다시 계산합니다.
- **워크스페이스 백업:** 명단·제출 좌석 지망·희망 동료·결과·좌석 좌표를 JSON으로 내려받습니다. 결과의 짝 배치·좌석 측 우선순위·시드를 포함해 검증·재현에 활용할 수 있습니다.
- **결과 CSV:** Excel에서 바로 읽을 수 있는 UTF-8 BOM 형식이며 희망 동료·실제 C짝 동료·충족 상태와 빈자리도 포함합니다.

`.local-data`, 빌드 결과, 브라우저 테스트 산출물은 Git에 포함되지 않습니다.

## 검증과 정적 빌드

아래 명령으로 구문·알고리즘·서버 입력 검증·정적 배포 파일을 확인할 수 있습니다. 이번 희망 동료 및 시트 양식 변경에는 해당 검증과 실제 브라우저 검증을 적용합니다.

```bash
npm run check
npm test
npm run build
```

- `check`: 애플리케이션·서버·매칭 모듈의 JavaScript 구문 검사.
- `test`: 안정 매칭, 동료 요청 최대 충족과 충돌·C짝 판별, 실제 지망 표시, 중복 없는 배정, 시드 재현성, 거리 비교, 23/24열 표 가져오기, 잘못된 선호, 동시 저장, 재시작 복원, 오래된 입력에 대한 결과 거부, 파일 취합을 Node 기본 테스트 도구로 검증.
- `build`: 정적 파일을 `dist/`에 생성. 정적 호스팅에서는 브라우저 저장과 표·파일 취합을 사용하며, Node 서버의 공유 저장 API와 공개 Google Sheets 링크 읽기는 제공되지 않습니다. `index.html`을 파일로 직접 열지 말고 HTTP 서버에서 제공해야 합니다.

실제 브라우저 검증 스크립트는 `tests/browser-smoke.mjs`에 있습니다. 실행할 환경에 Playwright와 Chrome이 있는 경우 다음처럼 사용할 수 있습니다. 앱 실행에는 Playwright가 필요하지 않습니다.

```bash
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs npm run test:browser
```
