# 자리 — sitting-app

13층 플랫폼개발팀의 **21개 좌석**에 대해 개인별 **1~21지망**을 입력하고, 같은 파트의 구성원이 가까이 앉도록 배정하는 웹 앱입니다. 게일–섀플리 안정 매칭과 파트별 거리 비교를 결합했습니다.

## 실행

**Node.js 22 이상**이 필요합니다. 외부 npm 패키지 설치 없이 실행할 수 있습니다.

```bash
git clone https://github.com/sunLeee/sitting-app.git
cd sitting-app
npm start
```

브라우저에서 **http://localhost:5180**을 엽니다. 서버를 종료할 때는 실행한 터미널에서 `Ctrl+C`를 누릅니다.

이미 내려받은 프로젝트에서는 프로젝트 폴더에서 `npm start`만 실행하면 됩니다. 포트가 사용 중이면 다른 포트를 지정하세요.

```bash
npm start -- --port 5181
```

기본 서버는 `127.0.0.1`에 연결됩니다. 같은 네트워크의 다른 기기에서 함께 입력할 때는 다음처럼 실행하고, 참여자는 서버를 실행한 컴퓨터의 IP 주소로 접속합니다.

```bash
npm start -- --host 0.0.0.0 --port 5180
```

참여자별 로그인은 구현되어 있지 않으며, 이름 선택으로 선호를 입력하는 내부 워크스페이스입니다.

## 사용 방법

1. **좌석 둘러보기**에서 구역과 실제 좌석 사진을 확인합니다.
2. **내 자리 선호**에서 본인 이름을 선택합니다.
3. 지도에서 좌석을 누르면 1지망부터 차례대로 추가됩니다. 중복 선택은 추가되지 않습니다.
4. 드래그 또는 위·아래 화살표로 순위를 바꿉니다. **남은 순위 자동 채우기**로 남은 좌석을 채운 뒤 수정할 수도 있습니다.
5. 21개 좌석을 모두 선택하고 **선호 저장하기**를 누릅니다. 수정 중인 순서는 브라우저에 임시 저장되고, 배정에는 제출한 선호만 사용합니다.
6. 모든 참여자가 제출하면 **배정 시작하기**에서 시드와 배정 기준을 정합니다.
7. 결과 지도와 표에서 개인별 좌석·배정 지망을 확인하고 **CSV**를 내려받습니다.

**미리 체험하기** 또는 `http://localhost:5180/?demo=1`은 예시 선호로 동작합니다. 예시 화면의 저장·배정·명단 수정은 실제 워크스페이스에 반영되지 않습니다.

## 좌석과 참여자

구역과 파트의 색상은 서로 다른 구분입니다.

| 구역 | 좌석 수 | 좌석 번호 | 전동 책상 | 모니터 | 좌/우 파티션 |
| --- | ---: | --- | --- | --- | --- |
| A | 9 | 207, 206, 205, 68, 69, 70, 73, 72, 71 | 있음 | 싱글 | 있음 |
| B | 6 | 79, 78, 77, 80, 81, 82 | 있음 | 싱글 | 없음 |
| C | 6 | 85, 90, 86, 89, 87, 88 | 없음 | 싱글 | 있음 |

| 파트 | 색상 | 초기 인원 |
| --- | --- | ---: |
| 데이터 | 파랑 | 8명 |
| 배차 | 노랑 | 8명 |
| 맵 | 빨강 | 4명 |

제공된 명단의 초록색 인원은 제외했습니다. 초기 참여자는 **20명**이므로 **1석이 비어 있게** 배정합니다. **참여자 관리**에서 이름과 파트를 수정하거나 최대 21명까지 추가할 수 있습니다. 명단 또는 제출 선호가 바뀌면 기존 결과를 해제하고 다시 배정합니다.

좌석·명단의 초기값은 `data.mjs`에서 관리합니다. 사진은 제공된 좌석 안내 이미지에서 추출했습니다.

## 배정 기준

### 파트가 가까워지는 배정 — 기본값

1. 데이터·배차·맵 파트의 기준 좌석을 서로 다른 좌석에 둡니다. 21석의 모든 기준 좌석 조합은 `21 × 20 × 19 = 7,980`개입니다.
2. 각 좌석은 가까운 기준 좌석을 가진 파트의 참여자를 우선합니다. 같은 파트 또는 거리 동률에서는 **시드로 정한 좌석별 우선순위**를 사용합니다.
3. 참여자는 본인의 1지망부터 제안합니다. 좌석은 현재 제안자 중 우선순위가 높은 사람을 유지하고, 밀려난 사람은 다음 지망에 제안합니다. 이 과정이 **참여자 제안형 게일–섀플리**입니다.
4. 각 후보에서 같은 파트에 속한 **모든 두 사람 사이의 유클리드 거리 합**을 계산합니다.
5. 기준 좌석 후보 7,980개와 파트 거리 우선순위가 없는 기본 후보 1개, 총 **7,981개** 중 거리 합이 가장 작은 결과를 선택합니다. 거리 합이 같으면 평균 배정 지망이 더 좋은 후보를 선택합니다.

게일–섀플리는 고정된 양측 선호에 대한 안정 매칭을 보장합니다. 이 앱은 **탐색한 안정 매칭 후보 중 최소 거리**를 선택하며, 모든 가능한 배치에 대한 **전역 최솟값을 증명하는 방식은 아닙니다**. 최종 결과의 안정성은 선택된 후보의 좌석 측 우선순위를 기준으로 검증합니다.

거리 좌표는 이미지의 상대 배치를 재현한 값이며 **미터 단위가 아닙니다**. 실측 거리로 계산하려면 `data.mjs`의 좌석 `x`, `y`를 실측 값으로 바꾸면 됩니다.

### 개인 선호 기준 배정

파트 거리에 따른 우선순위 없이 시드로 좌석 측 우선순위를 정한 뒤, 동일한 게일–섀플리 방식으로 배정합니다. 개인별 지망이 제안 순서에 반영되며, 전체 지망 순위 합의 전역 최적화를 보장하지는 않습니다.

동일한 명단·선호·좌석·시드·배정 모드는 동일한 결과를 만듭니다. 처리 순서에 따라 유불리가 달라지지 않도록 참여자·좌석 ID를 정렬해 계산합니다. 배정 계산은 Web Worker에서 진행됩니다.

## 저장과 파일 취합

- **Node 서버 실행:** 제출된 선호와 명단, 결과를 `.local-data/workspace.json`에 저장합니다. 같은 서버에 연결한 브라우저끼리 제출 내역을 공유하며, 서버 재시작 후에도 유지됩니다. 다른 브라우저의 저장 내역은 주기적으로 새로 확인합니다.
- **개인 임시 순서:** 각 브라우저의 `localStorage`에 저장합니다. 저장 버튼을 누르기 전까지 서버의 제출 내역을 바꾸지 않습니다.
- **개인 선호 파일:** 21개 순서를 선택한 뒤 **내 선호 파일 내려받기**로 JSON을 내보냅니다.
- **파일 불러오기:** 개인별 파일을 취합하거나 전체 워크스페이스 백업을 가져옵니다. 개인 파일은 해당 참여자의 선호를 합치며, 전체 백업은 파일의 명단을 함께 적용합니다. 가져온 결과는 그대로 사용하지 않고 최신 선호로 다시 계산합니다.
- **워크스페이스 백업:** 명단·제출 선호·결과·좌석 좌표를 JSON으로 내려받습니다. 결과의 좌석 측 우선순위와 시드를 포함해 검증·재현에 활용할 수 있습니다.
- **결과 CSV:** Excel에서 바로 읽을 수 있는 UTF-8 BOM 형식이며 빈자리도 포함합니다.

`.local-data`, 빌드 결과, 브라우저 테스트 산출물은 Git에 포함되지 않습니다.

## 검증과 정적 빌드

```bash
npm run check
npm test
npm run build
```

- `check`: 애플리케이션·서버·매칭 모듈의 JavaScript 구문 검사.
- `test`: 안정 매칭, 중복 없는 배정, 시드 재현성, 거리 비교, 잘못된 선호, 동시 저장, 재시작 복원, 오래된 입력에 대한 결과 거부, 파일 취합을 Node 기본 테스트 도구로 검증.
- `build`: 정적 파일을 `dist/`에 생성. 정적 호스팅에서는 브라우저 저장과 JSON 파일 취합을 사용하며, Node 서버의 공유 저장 API는 제공되지 않습니다. `index.html`을 파일로 직접 열지 말고 HTTP 서버에서 제공해야 합니다.

실제 브라우저 검증 스크립트는 `tests/browser-smoke.mjs`에 있습니다. 실행할 환경에 Playwright와 Chrome이 있는 경우 다음처럼 사용할 수 있습니다. 앱 실행에는 Playwright가 필요하지 않습니다.

```bash
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs npm run test:browser
```

| --- | --- |
| `index.html`, `styles.css`, `app.mjs` | 화면과 좌석·선호·명단·파일·결과 흐름 |

| `tests/` | 매칭·서버·브라우저 검증 |
| `scripts/` | 구문 검사와 정적 빌드 |
